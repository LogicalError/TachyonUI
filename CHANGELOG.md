# Changelog

Notable changes per release. Releases are tagged `vX.Y.Z`; the version lives in
`CMakeLists.txt` and is available in code from `gui_core/gui_version.h`.

## [Unreleased] — 0.1.0

First public preview. The API is not stable yet.

- Immediate-mode style GUI library for C++20 on Vulkan and SDL3 (`gui_core`, `gui_controls`).
- CSS-like styling with a dark and a light theme; text shaping, bidi and font fallback through skribidi.
- Flex and grid layout, docking with saved layouts, tables, tree views, grid views, node view, color and gradient pickers, menus, tooltips and toolbars.
- UI scaling that follows the display, with stored sizes in CSS pixels.
- Retained render cache for panels that haven't changed.
- CMake package: `find_package(TachyonUI)` with `TachyonUI::gui_core` and `TachyonUI::gui_controls`; Windows x64 with MSVC.
- No files or DLLs to ship: the shaders, the default themes and the fonts are built into the library (`TACHYON_EMBED_RESOURCES`), and the bundled SDL3 is linked statically. `SetResourceRoot` is only needed for an app's own themes and fonts; a file there replaces the built-in one of the same name.
- `GraphicsContext::SetShaderDirectory` is gone; `VulkanGraphicsContext::SetShaderDirectory` loads shaders from disk instead of the built-in ones. The package no longer installs `shaders_compiled/`.
- `TACHYON_SDL_TARGET`: the SDL target the libraries link (`SDL3::SDL3-static`, or the host's `SDL3::SDL3`), for a host that calls SDL too.
- `build.bat` / `build.sh` and `CMakePresets.json`; every example runs from any folder.
- A step-by-step tutorial (`docs/tutorial.md`) whose code is the `examples/tutorial` app, kept in sync by tests.
- The guides' landing page (`docs/README.md`) is about using the library only; the steps for building the API reference locally are gone.
- The README lists the requirements per OS; the CMake options and running the tests are on the wiki.
- The guides are rewritten to be short and to the point; what they say about the API is unchanged.
- Every control in the guides has a short usage example, and the API reference lists the controls by family under API by topic (fields, sliders, buttons and the rest).
- `Dropdown`: pick one of a list of options; the list opens on the current option.
- `AutocompleteField`: a text field that lists the suggestions matching what's typed.
- Keyboard focus: Tab reaches every control (not disabled ones, which also ignore keys) and every control shows it has the focus; [Writing a control](docs/contributing/writing-controls.md) lists what each control must do.
- Saved windows remember their monitor: they come back on it, or at the same place on a monitor of the same size, or on the primary one inside its work area when it's gone.
- Node view: keyboard focus moving to a node out of view pans the view to it.
- `SetTooltip`, `BeginTooltip` and `BeginContextMenu` without a target go on the whole control just drawn, not its last part; a color field's, breadcrumb's or vector field's tooltip and context menu work over each of its parts.
- Context menus open from the keyboard (Shift+F10, the Menu key); tabs close on Ctrl+W / Ctrl+F4; Alt + an arrow moves list rows, tabs and table columns; table headers sort with Space / Enter; the color picker's square and strips take the arrow keys; the node view moves, selects, collapses, pans and zooms from the keyboard.
- Escape closes the color picker and gradient editor as Cancel. The message dialog lets Tab reach all its controls, and takes Esc and its Alt mnemonics from any of them.
- Every control has the four forms (an ID or the call site, a style or the theme's): style overloads for the fields, sliders, dropdowns, menu items, status text, command search and message dialog; call-site forms for the containers, tables and tree, grid and list views; `Checkbox` with a `bool&`; list and dictionary fields take an ID like the others. A control's parts get IDs under its own.
- Sliders, slider fields, a number field's label drag, color, gradient and dropdown fields report a change (return value and `IsModified`) like the other fields; a clicked tab takes the focus; menu items' parts are no longer Tab stops.
- Color and gradient swatches show keyboard focus with an accent border, like the fields next to them.
- Rendering: circles are drawn exactly round, as a primitive of their own (they were four Bezier curves); dots are one triangle each, clipped per pixel; box-shaped primitives are drawn from an index buffer, four vertices each. `SDFGradient` runs from a shape's edge to its deepest point for every primitive.
- A cached scope's output (`BeginCached`, docked panels) stays on the GPU: drawing it again, moved or not, uploads nothing.
- Opaque boxes hide what was drawn under them on the GPU: the depth buffer now holds the draw order, and fragments an opaque box covers are skipped.
- Uploads (each frame's primitives, cached scopes, images) are copied on a thread of their own while the frame's commands are recorded.
- Text is laid out again only when its font, metrics, decoration lines or `TextLayoutStyle` change: a state that only recolors it (a hover, say) keeps the layout, and drawing at another width keeps its measurement. Decoration lines are drawn in their `text-<line>-color` (they were drawn in the text color); a line without one takes the text color.
- Style data: `TextStyle` holds only what text is laid out from; its `color` is gone (use `StyleState::textColor`) and the decoration colors moved to `StyleState::decorationColors`, indexed by `DecorationLine`. `TextLayoutStyle` moved from `VisualTextStyle` to `LayoutStyle`. `Style::states` is indexed by `ElementState` in place of the `Style::kNormal`, `kHover`, ... constants. The style for a box drawn without one is registered by `StyleManager` (`FallbackStyle()`), not by the theme.
- Buttons, toggles, dropdowns, fields, icon and title-bar buttons, dialog buttons, tab close buttons and table headers compute their hover and pressed backgrounds: their text color at 8% (hovered) and 14% (pressed) over their background, also when on or focused (`-tachyon-state-layer: content`; `StyleManager::ApplyStateLayer`). They used the fixed `--bg-active` and `--bg-pressed`, so pressed often looked like hovered and a control that was on didn't change under the pointer; rows, menu items and the check box keep their own.
- Moving the pointer from one menu item to the next, the item left blends out: it stayed lit for a frame (its focus, which looks like hover, had not moved yet) and then snapped off. A focus or press that changes while the UI is built or in a handler now starts its transition too; it was only seen when it changed during input.
- Documents: a level above panels, each document (`Document`) with its own panel layout. `Documents(id, set)` draws the document bar under the title bar and the active document's panels below it; switching the tab swaps the whole workspace. Each tab is tinted in its document type's color (`document-tab-<kind>`: level, material, layout, prefab and animation in the themes), the active one solid, with the type icon, the name and a muted extension, a dot while unsaved and a close button on the active or hovered tab; the line under the bar is in the active document's color. Tabs reorder by dragging; an "N open" list names every document and "+" calls `DocumentSet::onNew`. Closing (the button, the context menu, Ctrl+W) asks `DocumentSet::onClose` first. `CreateDocument` / `CloseDocument`; closing destroys the document's panels and its torn-off panel windows, and Dock on a panel torn from a hidden document shows that document first. The showcase opens six documents and asks before closing the unsaved one.
- Document windows: a document tab dropped on another document bar moves the document there (a phantom tab shows where it goes); dropped anywhere else, `DocumentSet::onTearOff` gets the document for a new main window, whose preview follows the cursor. Document tabs only drop on document bars and panel tabs only on panel docks. `EmitFloatingDockWindows(set)` builds the windows of the panels torn from a set's documents, so they belong to that document's main window and move with it. The showcase opens a main window with its own menus and status bar for each document dragged out, closes one left with no documents, and gives a closed one's documents back to the first.
- Wrapping text grows its element: text with `text-wrap: wrap` (or `word-char`) in an element whose height isn't fixed is as tall as its lines at the width the layout gives it, and its parents grow to hold it. It stayed one line tall, the rest cut off.
- Property help: `SetTooltip(PropertyHelp{ title, description, footer })` shows a larger tooltip on the popup surface, the description wrapping and the footer (where it lives in the API, its type) in a monospace font under a line; a `Label` or `DragLabel` given help is underlined, dotted. Tooltips have a soft shadow (`--shadow-tooltip`, `--shadow-popup`), and the see-through room for it reaches past the edge of the screen, so the box lines up with its target there too (`LayoutOverride::Overhang`).
- Tooltips point at their target's text: a label's tooltip text starts where the label's does, an end-aligned one ends where it ends, a button's is centered on its text; a target without text (or under a canvas's pan and zoom) gets it centered underneath. Kept on the screen by moving along, not narrowing.
- `SetErrorTooltip`: why a value isn't accepted, on the popup surface with an error border and arrow; a field inside `BeginInvalid` gets an error icon at its end, its text kept short of it.
- Disabled controls show their tooltip (`InteractionState::GetHoveredDisabledID`); `SetDisabledTooltip` adds why, on a muted second line. A tooltip declared inside `BeginDisabled`, `BeginSelected` or `BeginInvalid` is no longer disabled, selected or invalid itself.
- Node pins have tooltips: `NodeProperty::name`, `type` and `value` (asked for only while it shows), and a wired input's source ("from Noise.Value").
- A popup anchored to something in a panned or zoomed canvas (a pin's tooltip, a field's dropdown in a node) is placed where that is on the screen (`ElementStorage::ElementRectOnScreen`).
- Text cut short (an ellipsis, or a tree or list row in a narrow panel) shows whole on hover, in a tooltip lying right over it: its text where the cut text is, in the same font, so it reads as the text growing (`tooltip-expand`). It comes by itself; a tooltip of the target's own shows instead. `StyleManager::WithTextOf` gives a style the text of another as it is in a state.
- Text decorations set in a style (`text-underline-thickness` and the like) are drawn: with a language set for all text, every text lost the last attribute of its style, the decoration or its own language.
- Tooltips: a box with an arrow toward the target near the end it lines up with, below the target or above it when there's no room below, in their own colors (a light box on the dark theme, a dark one on the light theme). `SetTooltip(..., shortcut)` puts the keys that do the same in a chip after the text; `CommandButton` shows its command's. Moving from one tooltip to the next target shows the next at once, a tooltip stays 100 ms after its target is left, and none shows while a mouse button is held.
- Triangles (`RenderTriangle`, `RenderPolygon`) keep their size: their soft edge is half a pixel either side of the edge, like lines and circles, instead of all outside it, and it is no longer cut off past their corners. `RenderTriangle` takes the edges it shares with another triangle (`TriangleEdges`), drawn without one so no seam shows; `RenderFilledPolygon` and the gradient editor's stop markers use it.
- Popups flipped to the other side of their target for room keep their gap from it (a dropdown list or a tooltip opened above its field sat over it), and a popup flipped or kept on the screen at its right edge stays there (it went back off the screen).
- Toasts and banners: `ShowToast` shows a toast (severity circle, title with how long ago, a body that wraps, monospace for code, an optional progress bar, text-button actions; `age` for something that happened earlier) in the corner of the window that calls `Toasts()`, newest nearest the corner, older ones past four in a "+N earlier" pill. Errors stay until dismissed, the rest go after about 6 s (not while pointed at, nor while a progress bar is short of the end); they slide in and out from the right. `FindToast` changes a shown one, `DismissToast` takes it away. `Banner` puts a message across the top of a panel in its severity's tint, with buttons or a link on the right. The showcase has Help > Show Notifications and banners on its Inspector.
- Saved documents: `PersistDocuments` keeps the documents of each main window (name, extension, kind, order, the active one, each one's dock tree) and the window's place. After `RestoreUIState`, `TakeSavedDocuments` hands them to the app, which makes them again; `RestoreDocumentLayout` lays a document's panels out as saved and `RestoreWindowPlace` puts a window back where it was. The showcase comes back with its documents and windows as they were; its dock is no longer saved on its own (`"dock"`).
- A tab dragged past the last one in its bar, over the "+N" button or what follows the tabs, goes last, and is shown there while it's dragged; it jumped back to where it was. A reorderable group's drop slots are its items only, not the other things in it. `TabBarOptions::dropArea` names an element around a tab bar that counts as the bar while a tab is dragged (the document bar's whole row and line).
- `BeginTab` / `EndTab`: a tab with more in it than its icon and text. `BeginTabBar` takes `TabBarOptions`: the close item's label, no "+N" button, no layout menu.
- A list row being dragged (string list, float list, ...) shows its whole accent ring: the field in the row hid the ring's top and bottom edges unless it had the focus. The ring is drawn over the row's parts now (`.reorder-lifted-ring`), its fill still under them.
- Menus, dropdowns and other popups fade in over 120 ms, sliding 4px out from what they open from, and fade out over 80 ms; tooltips fade in over 100 ms without sliding. On Windows a window drawn with Vulkan can't be faded itself, so a layered stand-in window shows its frame while it fades and the popup is cloaked (in) or hidden (out) meanwhile (`IWindowBackend::ShowFade` / `MoveFade` / `EndFade`; elsewhere popups show and hide at once). Switching to another palette crossfades: each window's last frame in the old theme fades out over the new one in 200 ms. Reduced motion turns both off. `ReadWindowPixels` reads any window's last frame, not only a render-to-image window's.
- A box blending between two states blends colors of different hues (blue to red, ok to warning to error) in Oklab, so the middle keeps the ends' lightness and saturation instead of going dark and grey; greys and shades of one hue blend in sRGB as before. A translucent color drawn over a box (`Element::colorStyleIndex`, a swatch) keeps its color: it was drawn brighter.
- `BeginInvalid` / `EndInvalid` (and the `Invalid` scope): controls whose value isn't accepted show an error border (`--error`) and a 3px error halo (`--invalid-halo`) over whatever state they are in; the halo grows in over 150 ms. The element carries `ElementState::Invalid`, which isn't a style slot. The showcase's Settings > General > User name is invalid while empty. `StyleManager::RegisterOutline` registers a border-only box style once.
- A disabled control is drawn at 40% opacity as a whole, box, text and icons (menu items at 45%), from the theme's `--disabled-opacity`; disabled controls used to look like enabled ones, apart from menu items, whose text was a dimmer color. The CSS `opacity` property (0 to 1, per state) fades an element and everything in it; a faded box no longer hides what is under it on the GPU. A numeric custom property keeps its fraction (`--x: 0.4` was read as 0). `GUIRenderer::SetOpacity` fades what is drawn after it; `StyleManager::GetOpacity` reads a style's.
- State changes have their own timings and easing: hover in 70 ms and out 140 ms, release 120 ms, focus 100 ms (ease-out, `cubic-bezier(0.2, 0, 0, 1)`); a press is instant. Before, each of them blended over 100 ms. A switch, check box or toggle turning on or off blends over 120 ms (ease-in-out), the switch knob sliding across with it; a control part takes part with `ElementFlags::AnimatesSelected`. Reduced motion makes every change instant: it follows the OS setting, and `GUIApplication::SetReducedMotion` sets it (the showcase has it under Settings > Appearance > Motion). `CubicBezier` and `Easing::EaseOut` / `EaseInOut` are the timing curves; `CustomDrawContext::RenderBox` also draws a box part way between two of its states.
- Context menus opened by a right-click open at the pointer, not below the whole target (a tab bar on several rows put its menu under the last row). From the keyboard they still open below the target.
- Tab bars: the context menu of the strip, of any tab or of the "+N" button puts the bar's tabs on several rows ("Multiple Rows": every tab shown, wrapping) or back on one row with the "+N" button ("Collapse Rows"), for that bar only. `BeginTabBar` takes an optional `TabBarLayout*` to keep the choice; docked tab groups keep it on their dock node, in the saved layout (layouts saved before still load). `StyleManager::WithFlexWrap` gives a style's wrapping variant.
- A hovered row in tables, tree views, lists and grid views (the file panel too) shows plainly: `--bg-hover` is the hover state layer, `--text-1` at 8% over the panel (#232529 dark, #E9E9EB light), where most rows used `--bg-header`, barely lighter than the panel. A pressed or focused list item no longer looks fainter than a hovered one.
- Layout: each column of a wrapping flex column shares out its own free height with `flex-grow` / `flex-shrink`, as each line of a wrapping row does across, and keeps the columns it was broken into. `justify-content` places the rows of a column that doesn't wrap (it was ignored there). Layout runs one vertical sizing pass over the tree instead of two: only a wrapping column needs heights before it is positioned, and it sizes its own subtree.
- Every press-and-drag goes through one helper, `PointerDrag`. A press becomes a drag once the pointer has moved 4 CSS px in a straight line (`IsDragTravel`), the same for every control, drag and drop and text (moving a node and dragging a label now wait for it too). Escape (on key down) cancels any drag and puts back what it changed: also for the integer slider, the scrollbar, the color picker's square and strips, gradient stops, node moves, wire lanes, a box select, a right-button pan, the minimap and a floating toolbar's window. Drags measure in layout space, so sizers, label-group widths and table columns follow the cursor under a zoom. A gradient stop no longer jumps to the cursor when grabbed, and the minimap no longer follows a drag that started elsewhere.
- Double-clicks use the OS's double-click time (`DoubleClickMilliseconds`, read from the window backend each frame) instead of 300 ms; `DoubleClickTracker::IsDoubleClick`.
- `MakeHorizontalSizerHandler` and `MakeVerticalSizerHandler` take the `ElementStorage` after the `GUIStateManager`. `InputManager::IsDragAbandoned` tells a drag kept outside an element's events that its release won't come.
- Each window's frame is timed on the GPU (`VulkanWindowContext::LastGpuFrameSeconds`).
- Links in rich text take their cursor from `LinkStyle::cursor`, and `theme.linkStyle` from the theme's `.link` class (color, hover color, cursor). Links in padded or vertically centred text are found where they are drawn.
- CSS `text-shadow`: up to two shadows or glows under text, its decorations and its icon, blurred from the glyph atlas' distance field (now wider, so a blur has room).
- CSS `:first-child`, `:last-child` and `:only-child` for the box properties (backgrounds, borders, shadows, margin, padding, gap, cursor). Button and toggle group items use one class, `group-button` / `group-toggle`, in place of `first-`, `mid-` and `last-button` / `-toggle`; style the ends with `:first-child` and `:last-child`.
- Tab bars no longer wrap: the tabs that don't fit are listed by a "+N" button after the others, and the selected tab is always shown.
- `IFileSystem`: what a file view reads and changes (a folder's entries, moves, renames, and copying a file or folder in from the disk with `Import`). `MemoryFileSystem` keeps it in memory, filled by hand or copied from a disk folder as it's browsed; its changes never reach the disk.
- `FileIcons`: the OS's icon for a file, one per extension (the Windows shell's; none elsewhere). `ITextSystem::RegisterIconFromPixels` makes an icon of RGBA pixels, drawn in its own colors on its own and in text.
- The showcase's Files panel browses a copy of the workdirectory (or `--files <folder>`) with the OS's file icons; moves and renames stay in memory, and a refused one says why in a toast.
- Tooltips no longer blink under the pointer: their windows let the pointer, clicks and drops from other applications through to what's under them (a window element's `NoInput` becomes `WindowFlags::NoInput`; on Windows, a layered window that's click-through).
- Files and text dragged from other applications: the elements under them get `EventType::FileDragOver` (return true to take the drag; `FileDragTargetID` is then that element) and `EventType::FileDrop` with the paths in `InputState::droppedFiles`. A drop no element takes goes to `SetFileDropHandler`'s handler. The SDL backend forwards SDL's drop events (`IPlatformInputHandler::OnFileDrop`); behind a modal window nothing is dropped.
- `FileThumbnails`: a file's thumbnail, as Explorer shows it (a picture's contents, a frame of a video), read from the Windows shell off the UI thread and kept by path, modification time and size, at most so many; none elsewhere. `FileEntry` has the file's place on the disk (`disk`) and its last write (`modified`), also for an imported one. `ITextSystem::UnregisterIcon` lets go of an icon from pixels.
- The showcase's Files panel shows files on the disk in their thumbnails, with the type's icon until one is ready and for a file without one.
- The showcase's Files panel takes files and folders dropped from other applications into the folder under the pointer (a folder in the grid or the tree, else the one on view), through `IFileSystem::Import` (in its copy); that folder shows open while they're over it. A drop anywhere else is noted in the log.
- Files dropped from other applications reach elements in a cached panel (the showcase's Files panel): a panel drawn from its capture has nothing in it to take them, and the OS sends no mouse moves while another application drags. It's built again under the drag, and a drop on it waits a frame for that.
- Text cut short under an icon (a grid's item) shows whole on its own line, where it's drawn, without the icon; it covered the whole item. `ITextSystem::GetTextHeightWithoutIcon` gives how high a text is without the icon its measurement has in it (a text system of your own implements it). `StyleManager::WithTextOf` can leave out the other style's vertical padding.
- `VulkanGraphicsContext::AddFrameWait(semaphore, value, stages)`: the GUI's next frame waits for a timeline semaphore, for an image written on another queue (async compute) without going through the GUI's queue. The GUI's device needs `timelineSemaphore` (in `GetDeviceRequirements`).
- The showcase's F11 (and View > Fullscreen) fullscreens the window it's pressed in, a torn-off document window too, and the View menu shows that window's state; it always took the main window.
